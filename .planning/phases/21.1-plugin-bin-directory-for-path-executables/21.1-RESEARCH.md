# Phase 21.1: Plugin bin directory & auto-save research discoveries - Research

**Researched:** 2026-04-05
**Domain:** Claude Code plugin bin/ PATH executables, GSD workflow patching, autonomous curation agents
**Confidence:** HIGH

## Summary

Phase 21.1 has two distinct workstreams: (1) creating a `bin/` directory at the plugin root so key scripts become bare commands on PATH during Bash tool calls, and (2) patching the GSD research-phase workflow to produce a `## General Discoveries` section in RESEARCH.md, then auto-saving valuable discoveries to Forgetful via a post-research curation agent.

The `bin/` directory feature landed in Claude Code v2.1.91 (April 2026). Files placed in a plugin's `bin/` directory are automatically added to the Bash tool's PATH while the plugin is enabled. This means `forgetful-client call-tool query_memory '{...}'` can replace `node ${CLAUDE_PLUGIN_ROOT}/scripts/forgetful-client.js call-tool query_memory '{...}'` in all SKILL.md files. The scripts themselves stay in `scripts/` as a library; `bin/` contains thin wrapper executables or symlinks.

For the auto-save curation agent, two architecture approaches were evaluated: (A) patching the GSD workflow to add a step after researcher returns, and (B) using a SubagentStop hook that fires when `gsd-phase-researcher` completes. Approach B (SubagentStop hook) is cleaner -- it runs autonomously without modifying GSD workflow orchestration logic, and SubagentStop hooks receive `last_assistant_message` (the researcher's full output) plus `agent_transcript_path`. However, SubagentStop hooks cannot inject context back to the main session, which is fine since the curation saves autonomously. The recommended approach is a **SubagentStop hook with a command-type handler** that spawns a Node.js script to: read the RESEARCH.md, extract General Discoveries, dedup-check against Forgetful, and save qualifying memories.

**Primary recommendation:** Create `bin/` with wrapper scripts for key executables. Use a SubagentStop hook (matcher: `gsd-phase-researcher`) to trigger autonomous curation of General Discoveries. Patch the researcher's system prompt to produce the new section.

## Architecture Patterns

### Part 1: bin/ Directory Structure

```
bin/
  forgetful-client        # Wrapper: exec node "$PLUGIN_ROOT/scripts/forgetful-client.js" "$@"
  git-base-branch         # Wrapper: exec bash "$PLUGIN_ROOT/scripts/git-base-branch.sh" "$@"
  git-diff-filtered       # Wrapper: exec bash "$PLUGIN_ROOT/scripts/git-diff-filtered.sh" "$@"
  git-identity            # Wrapper: exec bash "$PLUGIN_ROOT/scripts/git-identity.sh" "$@"
  gsd-plan-context        # Wrapper: exec node "$PLUGIN_ROOT/scripts/gsd-plan-context.js" "$@"
  gsd-project-context     # Wrapper: exec node "$PLUGIN_ROOT/scripts/gsd-project-context.js" "$@"
  gsd-discuss-context     # Wrapper: exec node "$PLUGIN_ROOT/scripts/gsd-discuss-context.js" "$@"
  gsd-milestone-save      # Wrapper: exec node "$PLUGIN_ROOT/scripts/gsd-milestone-save.js" "$@"
  curate-discoveries      # The curation script (Node.js)
```

**Wrapper pattern:** Each bin/ file is a thin shell wrapper that resolves `PLUGIN_ROOT` relative to itself and delegates to the actual script. This avoids duplicating logic while keeping scripts/ as the canonical source.

```bash
#!/usr/bin/env bash
exec node "$(dirname "$0")/../scripts/forgetful-client.js" "$@"
```

**Key requirements for bin/ executables:**
- Must have shebang line (`#!/usr/bin/env bash` or `#!/usr/bin/env node`)
- Must have execute permission (`chmod +x`)
- Claude Code adds `bin/` to PATH automatically when plugin is enabled
- Files are invokable as bare commands in any Bash tool call

### Part 2: GSD Research Patch for General Discoveries

**New patch:** `patches/patch-research-discoveries.sh`

This patch injects a `## General Discoveries` section instruction into the GSD researcher's output format. The patch targets the researcher's system prompt (which is embedded in the research-phase.md workflow and also invoked from plan-phase.md).

**Patch location in research-phase.md:** The researcher prompt is inside the `Task()` call at Step 4. The `<output>` section specifies the RESEARCH.md output path. The patch needs to add instructions for the `## General Discoveries` section in the researcher's `<additional_context>` block (which is already patched with Forgetful context injection).

**Patch marker:** `TB_PATCH: research-general-discoveries`

**Section format to inject into researcher instructions:**

```markdown
## General Discoveries

Findings from this research that are valuable beyond this specific phase. Only include
items that meet the save criteria below. If nothing qualifies, omit this section entirely.

Each discovery entry:
- **Title:** Concise descriptive title (max 200 chars)
- **Content:** Self-contained description with context (max 2000 chars)
- **Scope:** general | project
- **Domain:** The technical domain (e.g., "claude-code-plugins", "bash-scripting")
- **Confidence:** verified (confirmed via official docs) | reported (from community/single source)
- **Tags:** 2-5 descriptive tags

### Save criteria (include if ANY apply):
- Surprising or contradicts common assumptions
- Hard-won debugging knowledge (non-obvious failure modes, workarounds)
- Cross-project applicable (useful beyond this repo)
- Actionable and specific (not vague guidance)
- Temporal with clear expiry (e.g., "as of Claude Code v2.1.91, bin/ requires...")

### Skip criteria (exclude if ANY apply):
- One-off implementation detail specific to this phase only
- Already documented in CLAUDE.md or project docs
- Easily rediscoverable via standard documentation search
- Common knowledge in the domain
```

### Part 3: Post-Research Curation Agent

**Architecture: SubagentStop hook + command script**

```
hooks/hooks.json  (add SubagentStop entry)
  |
  +-- matcher: "gsd-phase-researcher"
  +-- type: "command"
  +-- command: "${CLAUDE_PLUGIN_ROOT}/bin/curate-discoveries"
  +-- async: true  (don't block the main session)
```

**Why SubagentStop hook (not workflow patch):**
1. Clean separation -- curation logic lives in the plugin, not patched into GSD
2. Fires automatically whenever any GSD researcher subagent completes
3. Doesn't require modifying GSD's orchestration (research-phase.md Step 5)
4. `async: true` means it runs in the background while the user continues
5. Gets `last_assistant_message` with the researcher's output including General Discoveries

**Why command type (not agent type):**
1. Agent-type hooks spawn a subagent with Read/Grep/Glob tools but NOT Bash -- we need Bash to call `forgetful-client`
2. Command type can run Node.js scripts that call the Forgetful HTTP API directly
3. Simpler, more deterministic -- no LLM judgment needed for the dedup/save logic itself

**Curation script flow (`bin/curate-discoveries`):**
1. Receive SubagentStop hook input via stdin (JSON with `last_assistant_message`)
2. Parse `last_assistant_message` for `## General Discoveries` section
3. If no General Discoveries section found, exit 0 (nothing to curate)
4. Parse individual discovery entries from the section
5. For each discovery:
   a. Query Forgetful with discovery title for dedup check
   b. Read CLAUDE.md from cwd for overlap check
   c. Apply save criteria programmatically
   d. If passes: create memory via forgetful-client
6. Log results to stderr (for debugging; stdout is captured by hook system)

**Important: The curation agent is a deterministic script, not an LLM agent.** The researcher (which IS an LLM) already applies judgment when writing General Discoveries -- it decides what's worth noting. The curation script only does mechanical dedup-checking and Forgetful API calls. This avoids the cost/latency of a second LLM call and keeps the pipeline reliable.

### Anti-Patterns to Avoid

- **Symlinks in bin/ instead of wrapper scripts:** The plugin cache system copies files. While symlinks are honored during copy, wrapper scripts are more explicit and debuggable.
- **Moving scripts to bin/ directly:** Keep scripts/ as the canonical location for the actual logic. bin/ should only contain thin wrappers that delegate.
- **Using agent-type hook for curation:** Agent hooks get Read/Grep/Glob but NOT Bash. The curation needs to call forgetful-client via Bash. Use command-type hook instead.
- **Patching GSD orchestration for curation:** Adding steps to research-phase.md Step 5 is fragile and couples tb's curation logic to GSD's internal structure. SubagentStop hook is cleaner.
- **Making curation synchronous:** The curation can take several seconds for dedup queries. Running it async avoids blocking the user.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Forgetful API calls | Custom HTTP client | `forgetful-client.js` (scripts/) | Already handles SSE, sessions, errors |
| GSD workflow patching | Manual sed edits | Existing patch infrastructure (patches/) | apply-all.sh, verify-patches.sh, idempotent markers |
| Markdown section parsing | Full markdown parser | Simple regex extraction | General Discoveries is a well-defined section with known format |
| Dedup checking | Fuzzy string matching | Forgetful's semantic query_memory | Forgetful already does semantic similarity; query with k=3, compare titles |

## Opus vs Sonnet for Curation: Research Finding

**Recommendation: Neither -- use a deterministic script.**

The phase description asks "Research whether strongest model (opus) is needed for curation agent quality or if sonnet is sufficient." After analysis, the optimal answer is that no LLM is needed for the post-research curation step.

**Rationale:**
1. The researcher (already running as opus in quality profile) applies all the judgment when writing General Discoveries
2. The researcher has the full context of what it researched and why findings matter
3. The post-research step only needs to: parse structured text, dedup-check against Forgetful, save qualifying entries
4. These are mechanical operations that a Node.js script handles more reliably than an LLM
5. An LLM curation agent would add cost (~$0.05-0.15 per research run) and latency (~10-30s) for no quality benefit

**If LLM judgment were needed:** Sonnet would be sufficient. The curation task (evaluate whether a finding is worth saving) is a well-defined classification problem, not a complex reasoning task. Sonnet 4.6 handles classification and evaluation tasks at near-opus quality for 5x lower cost. But a deterministic script is better here.

## Common Pitfalls

### Pitfall 1: Execute Permission on bin/ Files
**What goes wrong:** Scripts in bin/ fail silently because they lack execute permission.
**Why it happens:** Git tracks file permissions but some workflows lose them. New files created by editors default to 644.
**How to avoid:** Always `chmod +x bin/*` after creating files. Add a verification step that checks permissions.
**Warning signs:** "Permission denied" errors when Claude tries to call bin/ commands.

### Pitfall 2: Patch Ordering with Existing Patches
**What goes wrong:** New research-discoveries patch conflicts with existing forgetful-research-context patch.
**Why it happens:** Both patches target the same workflow file (research-phase.md) and potentially the same region.
**How to avoid:** Use distinct markers. New patch should insert AFTER the existing Forgetful context patch marker, not at the same insertion point. Test with both patches applied.
**Warning signs:** Garbled workflow file, missing patch markers after apply-all.sh.

### Pitfall 3: SubagentStop Hook Not Firing
**What goes wrong:** The curation hook never triggers after researcher completes.
**Why it happens:** Matcher value doesn't match the actual agent_type. GSD spawns subagents with `subagent_type="gsd-phase-researcher"` but the runtime agent_type might differ (e.g., the Task() call might normalize names).
**How to avoid:** Test with `claude --debug` and inspect SubagentStop events to confirm the exact agent_type value. Start with a broad matcher (no matcher = fires for ALL subagents) then narrow down.
**Warning signs:** Debug logs show SubagentStop events but with unexpected agent_type values.

### Pitfall 4: Hook Output Size Limit
**What goes wrong:** Curation script output exceeds the 10,000 character hook output cap.
**Why it happens:** Verbose logging of all dedup results and memory creation responses.
**How to avoid:** Keep stdout minimal (hook system captures it). Use stderr for debug logging. The curation runs async so stdout isn't shown to the user anyway.
**Warning signs:** Truncated output in hook logs.

### Pitfall 5: Circular Patch Application
**What goes wrong:** Patches reference `bin/` executables but the bin/ wrappers reference scripts/ files that don't exist yet on a fresh install.
**Why it happens:** Bootstrap order: patches are applied before bin/ is created, or vice versa.
**How to avoid:** GSD patches continue using `$PLUGIN_ROOT/scripts/` absolute paths (they work without bin/). Only SKILL.md files and new hooks use bin/ paths. The bin/ feature is additive, not a replacement for the existing approach.
**Warning signs:** Errors during `apply-all.sh` referencing missing bin/ commands.

### Pitfall 6: last_assistant_message Truncation
**What goes wrong:** The `last_assistant_message` in SubagentStop input is truncated and doesn't contain the full RESEARCH.md content.
**Why it happens:** The researcher's final message includes a structured return block but may be summarized by the hook system.
**How to avoid:** Don't rely solely on `last_assistant_message`. As a fallback, have the curation script also read the RESEARCH.md file directly from the known path pattern (`.planning/phases/*/RESEARCH.md`).
**Warning signs:** Curation script parses empty or partial General Discoveries section despite the researcher writing a full one.

### Patch Script Pattern (Existing Convention)

```bash
#!/usr/bin/env bash
set -euo pipefail

WORKFLOW="$HOME/.claude/get-shit-done/workflows/research-phase.md"
PLUGIN_ROOT="$(cd "$(dirname "$0")/.." && pwd)"
MARKER="TB_PATCH: research-general-discoveries"

if [ ! -f "$WORKFLOW" ]; then
  echo "SKIP research-phase-discoveries: workflow not found"
  exit 0
fi

if grep -q "$MARKER" "$WORKFLOW"; then
  echo "OK research-phase-discoveries: already patched"
  exit 0
fi

# Create temp file with patch content
TMPFILE=$(mktemp)
cat > "$TMPFILE" << 'PATCH_EOF'

<!-- TB_PATCH: research-general-discoveries -->
After writing the standard RESEARCH.md sections, if you discovered any findings valuable
beyond this specific phase, add a `## General Discoveries` section at the end...
PATCH_EOF

# Insert after the existing forgetful-research-context patch marker
sed -i '' "/TB_PATCH: forgetful-research-context/r $TMPFILE" "$WORKFLOW"
rm "$TMPFILE"

echo "OK research-phase-discoveries: patched"
```

Source: Existing patches/patch-research-phase.sh convention.

### Discovery Entry Parsing (Node.js)

```javascript
function parseDiscoveries(researchContent) {
  const section = researchContent.match(
    /## General Discoveries\n([\s\S]*?)(?=\n## |\n---|\Z)/
  );
  if (!section) return [];

  const entries = [];
  const entryBlocks = section[1].split(/\n### /).filter(Boolean);
  for (const block of entryBlocks) {
    const title = block.match(/\*\*Title:\*\*\s*(.+)/)?.[1]?.trim();
    const content = block.match(/\*\*Content:\*\*\s*([\s\S]*?)(?=\*\*Scope)/)?.[1]?.trim();
    const scope = block.match(/\*\*Scope:\*\*\s*(.+)/)?.[1]?.trim();
    const domain = block.match(/\*\*Domain:\*\*\s*(.+)/)?.[1]?.trim();
    const confidence = block.match(/\*\*Confidence:\*\*\s*(.+)/)?.[1]?.trim();
    const tags = block.match(/\*\*Tags:\*\*\s*(.+)/)?.[1]?.split(',').map(t => t.trim());
    if (title && content) {
      entries.push({ title, content, scope, domain, confidence, tags });
    }
  }
  return entries;
}
```

## Open Questions

1. **Exact agent_type value for GSD researcher**
   - What we know: GSD spawns with `subagent_type="gsd-phase-researcher"` in the Task() call
   - What's unclear: Whether the runtime `agent_type` in SubagentStop matches this exactly or gets normalized
   - Recommendation: Test with `claude --debug` during first implementation. Start with a logging-only hook to confirm the value before adding curation logic.

2. **plan-phase integrated research**
   - What we know: plan-phase.md also spawns `gsd-phase-researcher` in its Step 5
   - What's unclear: Whether the SubagentStop hook fires for researcher subagents spawned from plan-phase too (it should, since the hook is on the plugin level)
   - Recommendation: Verify during testing. If it fires for both standalone and integrated research, the curation works in both flows automatically.

3. **RESEARCH.md file path discovery in curation script**
   - What we know: SubagentStop provides `cwd` but not the specific RESEARCH.md path
   - What's unclear: Best way for the curation script to find the newly-written RESEARCH.md
   - Recommendation: Use `last_assistant_message` to extract the file path from the researcher's structured return ("File Created: ..."), or glob `.planning/phases/*/RESEARCH.md` sorted by modification time.
