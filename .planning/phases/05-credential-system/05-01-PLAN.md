  <action>
Create `scripts/setup-credential.js` that exports a single async function accepting a config object. The module supports two modes:

**Keychain mode** (config.mode = 'keychain'):
- Config fields: `{ mode: 'keychain', service: string, name: string, prompt: string, verify: async (value) => boolean | null }`
- Flow: (1) Check CLI arg `process.argv[2]` -- if present, optionally verify then store and exit. (2) Check existing value in Keychain via `node keychain.js get {service}` -- if found, print message and exit 0. (3) If no TTY (`!process.stdin.isTTY`), print error with usage hint and exit 1. (4) Interactive prompt with retry loop.
- Retry loop: up to 3 attempts. For each attempt: prompt user, trim input, if empty reject. If `config.verify` is not null, call it. If verify returns true, store via `node keychain.js set {service} {value}` and exit 0. If verify returns false, print "Verification failed" and re-prompt. After 3 failures, ask "Store anyway? (y/N)" -- if y, store; if n, exit 1.
- If `config.verify` is null (store-only mode like pr-upload), store immediately after prompt without verification.
- Distinguish HTTP 401/403 (bad token) from connection errors in verify. On connection error, offer to store anyway with warning.
- Use Node.js `readline` for prompting. Always `rl.close()` before `process.exit()`.
- Resolve keychain.js path via `path.join(__dirname, 'keychain.js')` (sibling file in scripts/).

**CLI-check mode** (config.mode = 'cli-check'):
- Config fields: `{ mode: 'cli-check', name: string, checks: [{ cmd: string, failMsg: string }] }`
- Flow: Run each check command via `execSync`. If any fails, print its failMsg and exit 1. If all pass, print success message and exit 0.

Use `#!/usr/bin/env node` shebang. Require only Node.js built-ins (child_process, path, readline).

**skills/sentry-investigate/setup.js** (keychain, API verification):
```javascript
#!/usr/bin/env node
const setup = require('../../scripts/setup-credential');
setup({
  mode: 'keychain',
  service: 'tb.sentry-token',
  name: 'Sentry auth token',
  prompt: 'Enter Sentry auth token: ',
  verify: (token) => {
    const https = require('https');
    return new Promise((resolve) => {
      const req = https.get('https://sentry.io/api/0/organizations/', {
        headers: { Authorization: `Bearer ${token}` }
      }, (res) => {
        res.resume();
        resolve(res.statusCode >= 200 && res.statusCode < 300);
      });
      req.on('error', () => resolve(null));
      req.setTimeout(10000, () => { req.destroy(); resolve(null); });
    });
  }
});
```
Note: verify returns `null` on connection error (distinct from `false` for bad token) so the shared base can offer store-anyway.
