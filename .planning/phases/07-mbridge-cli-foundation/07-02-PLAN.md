  <action>
    **src/mbridge/platforms/ios.py — xcrun simctl wrapper:**

    Helper function `require_xcrun()`: uses `shutil.which("xcrun")` to check availability. If missing, raise RuntimeError with install instructions for Xcode Command Line Tools. This is the lazy tool check pattern from user decisions.

    Helper function `run_cmd(args, parse_json=False)`: thin wrapper around `subprocess.run(args, capture_output=True, text=True)`. Raises RuntimeError on non-zero exit with stderr message. If parse_json=True, returns `json.loads(result.stdout)`.

    Function `list_devices()`:
    - Calls `require_xcrun()`
    - Runs `xcrun simctl list devices --json` via run_cmd with parse_json=True
    - Iterates `data["devices"].items()` — key is runtime string like `com.apple.CoreSimulator.SimRuntime.iOS-26-2`
    - Parses os_version from runtime key: extract after last dot, replace hyphens with dots (e.g., "iOS-26-2" -> "iOS 26.2"). Handle both "iOS" and other runtimes (tvOS, watchOS, visionOS) — extract the platform prefix and version.
    - Skips devices where `isAvailable` is False
    - Returns list of dicts with fields: id (from udid), name, platform="ios", type="simulator", state (lowercased), os_version

    Function `get_device_info(device_id)`:
    - Calls `require_xcrun()`
    - First gets base info by finding the device in `list_devices()` output matching device_id. Error if not found.
    - Tries to get screen dimensions via `xcrun simctl getenv <device_id> SIMULATOR_MAINSCREEN_WIDTH` (and HEIGHT, SCALE). These only work if the device is booted.
    - If getenv fails (device not booted), try `xcrun simctl io <device_id> enumerate` and parse text output for "Default width:" and "Default height:" lines. Scale may not be available from enumerate — omit if not parseable.
    - Gets runtime version from device type identifier (already available from list)
    - Gets data_path from the simctl list JSON (dataPath field)
    - Returns the base dict extended with screen (width, height, scale), architecture (use deviceTypeIdentifier to infer or just report "arm64" for Apple Silicon), runtime_version, data_path

    Function `boot_device(device_id)`:
    - Calls `require_xcrun()`
    - Runs `xcrun simctl boot <device_id>`. Catches error if already booted (simctl returns error for already-booted devices — detect "Unable to boot device in current state: Booted" or similar, and treat as success).
    - Returns `{"id": device_id, "status": "booted"}`

    Function `list_apps(device_id)`:
    - Calls `require_xcrun()`
    - Runs `xcrun simctl listapps <device_id>` — outputs plist. Parse with `plistlib.loads(result.stdout.encode())` (stdlib). If plistlib approach is too complex, use `xcrun simctl listapps <device_id> --json` if available, or fall back to listing bundle containers via `xcrun simctl get_app_container <device_id>`. Simplest approach: run `xcrun simctl listapps <device_id>` and parse plist output.
    - Returns list of `{bundle_id, name, version}` dicts

    Function `get_foreground_app(device_id)`:
    - This is tricky on simulators. Use `xcrun simctl spawn <device_id> launchctl list` and filter for UIKitApplication entries. Or use `xcrun simctl launch_activity_log`. Simplest: output an error message that foreground detection requires additional tools, or attempt a best-effort approach.
    - Return `{bundle_id, name}` or error if not determinable.

    Function `launch_app(device_id, bundle_id)`:
    - Runs `xcrun simctl launch <device_id> <bundle_id>`
    - Returns `{"id": device_id, "bundle_id": bundle_id, "status": "launched"}`

    Function `open_url(device_id, url)`:
    - Runs `xcrun simctl openurl <device_id> <url>`
    - Returns `{"id": device_id, "url": url, "status": "opened"}`

    **src/mbridge/platforms/android.py — adb wrapper:**

    Helper function `require_adb()`: uses `shutil.which("adb")` to check availability. If missing, raise RuntimeError with install instructions for Android SDK Platform-Tools.

    Helper function `run_cmd(args)`: same pattern as ios.py — subprocess.run wrapper with error handling.

    Function `list_devices()`:
    - Calls `require_adb()`
    - Runs `adb devices -l`
    - Parses output line by line, skipping first line ("List of devices attached") and empty lines
    - Skips devices with state "offline"
    - For each device line: split to get serial and key:value properties
    - Determine type: "emulator" if serial matches `emulator-\d+`, else "physical"
    - Get os_version via `adb -s <serial> shell getprop ro.build.version.release` (per-device subprocess call)
    - Get model name via `model` property from the -l output, or fall back to `ro.product.model` via getprop
    - Returns list of dicts: id (serial), name (model), platform="android", type, state="booted", os_version

    Function `get_device_info(device_id)`:
    - Calls `require_adb()`
    - Gets base info from list_devices() matching device_id. Error if not found.
    - Runs `adb -s <device_id> shell wm size` — parse both "Physical size:" and "Override size:" lines. Prefer override if present. Extract width and height as integers.
    - Runs `adb -s <device_id> shell wm density` — parse "Physical density:" and "Override density:" lines. Prefer override.
    - Gets architecture via `adb -s <device_id> shell getprop ro.product.cpu.abi`
    - Gets SDK version via `adb -s <device_id> shell getprop ro.build.version.sdk`
    - Returns base dict extended with screen (width, height, density), architecture, sdk_version

    Function `list_apps(device_id)`:
    - Runs `adb -s <device_id> shell pm list packages -3` (third-party apps)
    - Parses "package:" prefix from each line
    - Returns list of `{bundle_id}` dicts (Android pm list doesn't easily give app names or versions inline — keep it simple)

    Function `get_foreground_app(device_id)`:
    - Runs `adb -s <device_id> shell dumpsys activity activities | grep mResumedActivity` or `adb -s <device_id> shell dumpsys window | grep mCurrentFocus`
    - Parses package name from output
    - Returns `{bundle_id}` or error

    Function `launch_app(device_id, bundle_id)`:
    - Runs `adb -s <device_id> shell monkey -p <bundle_id> -c android.intent.category.LAUNCHER 1`
    - Returns `{"id": device_id, "bundle_id": bundle_id, "status": "launched"}`

    Function `open_url(device_id, url)`:
    - Runs `adb -s <device_id> shell am start -a android.intent.action.VIEW -d <url>`
    - Returns `{"id": device_id, "url": url, "status": "opened"}`

    **src/mbridge/coords.py — Coordinate conversion:**

    Function `logical_to_physical(x, y, scale)`: returns `(round(x * scale), round(y * scale))`. For iOS point-to-pixel conversion.

    Function `physical_to_logical(x, y, scale)`: returns `(round(x / scale), round(y / scale))`. For iOS pixel-to-point conversion.

    Docstrings explaining:
    - iOS uses point space (WDA coordinates). Convert: pointX = pixelX / scaleFactor
    - Android uses pixel coordinates directly from `wm size` (override if present). No conversion needed for adb input commands.
    - The scale factor comes from device info (iOS: SIMULATOR_MAINSCREEN_SCALE, Android: density is informational only)

    Replace the stub implementations in device.py and app.py with real platform calls.

    **device.py updates:**

    `list` command:
    - Import `ios.list_devices` and `android.list_devices` from platforms
    - If `--platform ios`: call only ios.list_devices(). Catch RuntimeError (xcrun not found) and call error().
    - If `--platform android`: call only android.list_devices(). Catch RuntimeError (adb not found) and call error().
    - If no --platform filter: try both platforms. For each, catch RuntimeError silently (it's fine if one platform's tools aren't installed). Concatenate results.
    - If both fail and result list is empty, output empty list (not an error — no devices is valid).
    - Call `output(devices)` with the combined list.

    `boot` command:
    - Determine platform by checking device_id against known devices (call both list_devices, find matching id) or by trying ios.boot_device first (simulators use UUIDs), then android if needed.
    - Simpler approach: try `ios.boot_device(device_id)` — if it fails with "not found" type error, the device isn't an iOS simulator. Android emulators are already booted via `adb` so boot is iOS-only. If device not found in either platform, call error().
    - Output the result JSON.

    `info` command:
    - Similar platform detection: try ios.get_device_info(device_id) first, if fails try android.get_device_info(device_id).
    - The get_device_info functions already error if device_id not found in their platform, so catch RuntimeError and try the other platform.
    - Output the result JSON.

    **Helper for platform detection:** Create a module-level or inline function `detect_platform(device_id)` that checks both platform list_devices results and returns "ios" or "android". Cache the device lists for the current invocation to avoid redundant subprocess calls.

    **app.py updates:**

    `list` command:
    - Detect platform for device_id, call appropriate platform's list_apps(device_id)
    - Output the result

    `foreground` command:
    - Detect platform, call get_foreground_app(device_id)
    - Output the result

    `launch` command:
    - Detect platform, call launch_app(device_id, bundle_id)
    - Output the result

    `open-url` command:
    - Detect platform, call open_url(device_id, url)
    - Output the result

    All commands wrap platform calls in try/except RuntimeError and call `error(str(e))` on failure. This provides clean JSON error output instead of Python tracebacks.

    After modifying device.py and app.py, reinstall the package: `cd tools/mbridge && uv tool install . --force`
