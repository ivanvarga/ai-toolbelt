<threat_model>
ASVS L1 threats relevant to this plan (deploy script + wrapper):

1. **Script injection via unsanitized paths in deploy script** — if `PLUGIN_VERSION` or `PAPERCLIP_ROOT` contains special shell characters (backticks, `$(...)`, spaces, newlines), the `rm -rf` or `cp -R` could escape. Mitigation: all paths quoted double-quotes throughout the script (existing behavior — audit retained). `PLUGIN_VERSION` comes from `ls | sort -V | tail -1` which is filesystem-derived (already trusted); `PAPERCLIP_ROOT` comes from `find ... -name adapter-utils` (trusted path). No payload-derived data flows into the script.
2. **Overwriting user files outside Paperclip dir** — if `PAPERCLIP_ROOT` is empty or `/`, `rm -rf "$PAPERCLIP_ROOT/companies/$name"` could be catastrophic. Mitigation: existing script already asserts `-d "$PAPERCLIP_ROOT/skills"` before proceeding; preserve + extend: also assert `-n "$PAPERCLIP_ROOT"`. Add guard: `[ -n "$PAPERCLIP_ROOT" ] && [ -d "$PAPERCLIP_ROOT" ] || exit 0`.
3. **Wrapper script exec with attacker-controlled env** — if `TB_TRIAGE_WORKTREE_NAME` env var (injected by Paperclip adapter at runtime) contains shell metacharacters, `claude --worktree "$TB_TRIAGE_WORKTREE_NAME"` could inject. Mitigation: wrapper uses `exec claude --worktree "$name"` (double-quoted — no interpolation). Additional: validate `$TB_TRIAGE_WORKTREE_NAME` against `^[a-z0-9-]+$` at top of wrapper; if invalid, exit 2 with stderr `"invalid worktree name"`.

Severity: MEDIUM (deploy script writes to user's filesystem outside the plugin dir). Gate: pass iff all 3 mitigations implemented.
</threat_model>

    Create `scripts/tb-triage-worktree-wrapper.sh`:
    ```bash
    #!/usr/bin/env bash
    set -euo pipefail

    : "${TB_TRIAGE_WORKTREE_NAME:?must be set by paperclip adapter}"

    if ! [[ "$TB_TRIAGE_WORKTREE_NAME" =~ ^[a-z0-9-]+$ ]]; then
        echo "invalid worktree name: $TB_TRIAGE_WORKTREE_NAME" >&2
        exit 2
    fi

    if [ -n "${TB_TRIAGE_WORKTREE_CWD:-}" ]; then
        cd "$TB_TRIAGE_WORKTREE_CWD" || {
            echo "cannot cd to $TB_TRIAGE_WORKTREE_CWD" >&2
            exit 3
        }
    fi

    exec claude --worktree "$TB_TRIAGE_WORKTREE_NAME" "$@"
    ```

    `chmod +x scripts/tb-triage-worktree-wrapper.sh`.

    This wrapper is intentionally 14 lines. The three validation branches implement threat-model mitigation #3:
    - Require `TB_TRIAGE_WORKTREE_NAME` set (fail fast otherwise)
    - Regex-validate against `^[a-z0-9-]+$` (only lowercase alnum + dash, per Claude Code's worktree naming)
    - Quote all interpolations (`"$TB_TRIAGE_WORKTREE_CWD"`, `"$TB_TRIAGE_WORKTREE_NAME"`)

    Wrapper is NOT referenced from `.paperclip.yaml` in this plan — Plan 04 already declared `extraArgs: ["--worktree", "{{...}}"]` on the assumption that templating works. IF at execution time it's confirmed templating is unsupported, a follow-up edit to `.paperclip.yaml` would change `adapter.type` or `adapter.command` to point at this wrapper.
