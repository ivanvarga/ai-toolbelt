    **Shared helper `_resolve_element(device_id, text, element_id, element_type, exact, unique)` in action.py:**
    Import `_capture_dump` from `mbridge.ui` and `find_elements` from `mbridge.parsing.query`. Call `_capture_dump(device_id)` to get elements, then `find_elements(elements, id=element_id, text=text, exact=exact, element_type=element_type)`. If no results: `error("No matching elements found")`. If `unique=True` and `len(results) > 1`: `error(f"Multiple matches found ({len(results)}): ...")` listing each match's label/type/center. Return `results[0]`.

    **Helper `_parse_text_segments(text)` in action.py:**
    Splits text into segments of `("text", str)` and `("key", escape_char)`. Scan character by character; when `\` followed by `n`, `b`, `t`, or `e` is found, emit the preceding text segment (if any) then emit the key segment with the actual escape char (`\n`, `\b`, `\t`, `\e`). Return list of tuples.

    **Helper `compute_swipe_coords(screen_width, screen_height, direction, distance_pct=0.5, start_x=None, start_y=None)` in action.py:**
    Default start is screen center. Compute end point based on direction and distance percentage of the relevant screen dimension. Clamp end coordinates to 0..screen_width and 0..screen_height. Return `(x_start, y_start, x_end, y_end)`.

    **Click subcommand `tap` under action group:**
    Arguments: `device_id` (required). Options: `--x` and `--y` (int, default None), `--text`, `--id`/element_id, `--type`/element_type, `--exact` (flag), `--unique` (flag).
    Logic: If `--text`/`--id`/`--type` provided, call `_resolve_element` to get element, extract center x/y. If `--x`/`--y` provided, use those directly. If neither, error. Detect platform via `_detect_platform`. Dispatch to `ios.tap` or `android.tap`. Output `{"status": "tapped", "x": x, "y": y}`.

    **Click subcommand `swipe` under action group:**
    Arguments: `device_id` (required), `direction` (required, type=Choice["up","down","left","right"]). Options: `--distance` (float, default 0.5), `--text`, `--id`/element_id, `--type`/element_type, `--exact` (flag), `--from` as `from_coords` (string "x,y", default None).
    Logic: Detect platform. Get screen info (`_get_screen_info`). If element flags provided, resolve element center as start. If `--from` provided, parse as start coords. Otherwise default to screen center. Call `compute_swipe_coords`. Dispatch to platform swipe. Output `{"status": "swiped", "direction": direction, "from": {"x": x1, "y": y1}, "to": {"x": x2, "y": y2}}`.

    **Click subcommand `type` (named `type_text_cmd` to avoid Python builtin) under action group:**
    Arguments: `device_id` (required), `text` (required). Options: `--text` as `element_text`, `--id`/element_id, `--type`/element_type, `--exact` (flag), `--clear` (flag).
    Logic: If element flags, resolve element and tap it first (using platform tap at element center). If `--clear`, clear field: detect platform, for iOS send 500x key_press(device_id, 42) -- actually move to end first with key code 119 (MOVE_END HID = not standard, just send 500 backspaces), for Android send keyevent(device_id, 123) (MOVE_END) then 200x keyevent(device_id, 67) (DEL). Parse text segments. For each segment: if "text" segment, call platform type_text; if "key" segment, look up platform key map and call key_press/keyevent. Output `{"status": "typed", "text": original_text}`.
