**hooks/user-prompt-context.js — add internal 3-second timeout:**

Wrap the entire try block's Forgetful operations (from `resolveForgetfulUrl()` through the stdout write) in a `Promise.race` against a 3-second abort timer. Use `AbortSignal.timeout(3000)` with an AbortController pattern or a simpler setTimeout+reject approach.

Concrete approach: Create a timeout promise that rejects after 3000ms. Race it against the existing Forgetful operations. If the timeout wins, the outer catch block handles it (writes failure flag on first failure, then exits 0).

The simplest implementation: replace the `try { ... } catch { ... }` block in `main()` with:

```javascript
const timeout = new Promise((_, reject) => setTimeout(() => reject(new Error('timeout')), 3000));
try {
  await Promise.race([async () => { /* existing Forgetful operations */ }, timeout].map(f => typeof f === 'function' ? f() : f));
} catch {
  // existing failure flag + notice logic
}
```

Or more readably, extract the Forgetful operations into an async helper function and race it:

```javascript
async function queryForgetful(prompt) {
  const url = resolveForgetfulUrl();
  if (!url) process.exit(0);
  // ... rest of existing try block body ...
}

// In main(), replace the try/catch:
const timeout = new Promise((_, reject) => setTimeout(() => reject(new Error('timeout')), 3000));
try {
  await Promise.race([queryForgetful(prompt), timeout]);
} catch {
  if (!fs.existsSync(flagFile)) {
    fs.writeFileSync(flagFile, '');
    outputFailureNotice();
  }
  process.exit(0);
}
```

Important: the setTimeout must NOT keep the process alive if the main path completes first. Use `unref()` on the timer: `const timer = setTimeout(...); timer.unref?.();` -- this ensures Node.js can exit naturally when the successful path finishes without waiting for the 3s timer to fire.
