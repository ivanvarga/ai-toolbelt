  <name>Task 1: Create query engine with element finding logic</name>
  <files>

  </files>
  <behavior>
    - find_elements(elements, id="login_btn") returns elements where accessibility_id == "login_btn"
    - find_elements(elements, text="Sign") returns elements where "Sign" is substring of label (case-sensitive)
    - find_elements(elements, text="Sign In", exact=True) returns elements where label == "Sign In" exactly
    - find_elements(elements, text="sign", exact=False) does NOT match "Sign In" (case-sensitive by default)
    - find_elements(elements, element_type="Button") returns elements where type == "Button"
    - find_elements(elements, text="Sign", element_type="Button") returns elements matching BOTH text AND type (AND combination)
    - find_elements(elements, id="nonexistent") returns empty list
    - find_elements(elements, xpath="//Button") returns all Button elements from tree
    - find_elements(elements, xpath="//Button[@accessibility_id='login_btn']") returns matching elements
    - find_elements with no filters returns all elements flattened from tree
    - find_elements searches through nested children (Android hierarchical trees)
  </behavior>
  <action>
    1. Create `tools/mbridge/src/mbridge/parsing/query.py`:
       - Import xml.etree.ElementTree as ET for XPath evaluation
       - `find_elements(elements, id=None, text=None, exact=False, element_type=None, xpath=None)`:
         - If xpath is provided, convert normalized element tree to an XML tree (using `_to_xml`), evaluate XPath via ElementTree, convert matching XML nodes back to normalized dicts. Return results.
         - If non-xpath filters: flatten the element tree recursively (including all nested children) into a flat list. Apply filters as AND:
           - id filter: element["accessibility_id"] == id
           - text filter with exact=False: text in element["label"]
           - text filter with exact=True: element["label"] == text
           - element_type filter: element["type"] == element_type
         - Return list of matching elements
       - `_flatten(elements)` -- recursively yields all elements and their children from nested tree
       - `_to_xml(elements)` -- converts normalized element list to an ElementTree. Create a `<root>` parent. For each element, create an XML node with tag = element["type"] and attributes: accessibility_id, label (mapped from element fields), enabled, visible (as strings). Recurse for children. Return root Element.
       - `_from_xml_node(xml_node)` -- converts an XML Element back to a normalized dict by reading tag and attributes. Needed to return results from XPath queries.
       NOTE: XPath attribute names in the XML must match the query syntax. Use element field names directly as XML attributes: accessibility_id, label, type (as tag name), enabled, visible. Bounds and center stored as attributes too: bounds_x, bounds_y, bounds_width, bounds_height, center_x, center_y.

    2. Write `tools/mbridge/tests/test_query.py`:
       - Create a sample normalized element list as test fixture (inline, 6-8 elements). Include:
         - A Button with label "Sign In" and accessibility_id "login_btn"
         - A Label with label "Welcome"
         - A TextField with label "" and accessibility_id "email_field"
         - A Button with label "Cancel" and accessibility_id "cancel_btn"
         - An element with children (to test nested search): a View containing a Button
       - Test find by id: find_elements(elements, id="login_btn") returns exactly 1 element
       - Test find by text substring: find_elements(elements, text="Sign") returns the Sign In button
       - Test find by text exact: find_elements(elements, text="Sign", exact=True) returns empty (no exact match for "Sign")
       - Test find by text exact match: find_elements(elements, text="Sign In", exact=True) returns 1 element
       - Test find by type: find_elements(elements, element_type="Button") returns all buttons (including nested)
       - Test combined filters: find_elements(elements, text="Sign", element_type="Button") returns 1 element
       - Test no match: find_elements(elements, id="nonexistent") returns []
       - Test xpath: find_elements(elements, xpath="//Button") returns all Button elements
       - Test xpath with attribute: find_elements(elements, xpath="//Button[@accessibility_id='login_btn']") returns 1 element
       - Test nested children searched: a Button inside a View's children is found by type filter
       - Test no filters: find_elements(elements) returns all elements flattened

    3. Run tests: `cd tools/mbridge && uv run pytest tests/test_query.py -x -q`. All must pass.

       `dump` subcommand:
       - `@ui.command()` with `@click.argument("device_id")`
       - Detect platform via `_detect_platform(device_id)` from device module
       - For iOS: call `ios.dump_ui(device_id)` to get raw JSON, get screen dims from `ios._get_screen_info(device_id)`, call `parse_ios_dump(raw, width, height)` to normalize, output result
       - For Android: call `android.dump_ui(device_id)` to get raw XML, get screen dims from `android._get_screen_info(device_id)`, call `parse_android_dump(raw, width, height)` to normalize, output result
       - Unknown platform: call `error(f"Device not found: {device_id}")`
       - Wrap in try/except RuntimeError, call error() on failure

       `find` subcommand:
       - `@ui.command()` with `@click.argument("device_id")`
       - Options: `--id` (str), `--text` (str), `--exact` (flag), `--type` (str, param name "element_type"), `--xpath` (str)
       - Self-contained: captures fresh dump internally (same dump logic as above), then queries via `find_elements(elements, id=id, text=text, exact=exact, element_type=element_type, xpath=xpath)`
       - Output the matching elements list via output()
       - If no filter flags provided, output all elements (find_elements with no filters returns everything)

Since ui.py needs it, import directly: `from mbridge.device import _detect_platform`.
