Create scripts/keychain.js -- a Node.js CLI script for macOS Keychain operations.

Interface: node scripts/keychain.js <get|set|delete> <service> [value]

Implementation:
- Use child_process.execSync to call macOS `security` CLI
- `get`: runs `security find-generic-password -s "<service>" -w`, outputs value to stdout (process.stdout.write, no newline), exits 1 if not found
- `set`: first tries `security delete-generic-password -s "<service>"` (ignore failure), then runs `security add-generic-password -s "<service>" -w "<value>"`. Requires value as 3rd arg.
- `delete`: runs `security delete-generic-password -s "<service>"`, ignores errors
- Validate action and service are provided, print usage to stderr and exit 1 if missing
- For `set`, validate value is provided
- All stdio for execSync calls: `['pipe', 'pipe', 'pipe']` to suppress security CLI output to terminal
- Add shebang: #!/usr/bin/env node
- No comments in file (per project CLAUDE.md)
- Use require() not import (CommonJS, no package.json type:module)

Reference the RESEARCH.md code example for the exact implementation pattern.

Create scripts/sentry-api.js -- Sentry API client for fetching issue and event data.

Interface:
  node scripts/sentry-api.js issue <org> <project> <issue_id>
  node scripts/sentry-api.js event <org> <project> <issue_id> <event_id>
  node scripts/sentry-api.js events <org> <project> <issue_id>

Implementation:
- Shebang: #!/usr/bin/env node
- Get Sentry auth token via: execSync(`node "${path.join(__dirname, 'keychain.js')}" get tb.sentry-token`, {encoding: 'utf8'}).trim()
- If token retrieval fails (execSync throws), print "Sentry token not found. Run setup for sentry-investigate skill." to stderr and exit 1
- Use Node.js built-in https module (no dependencies) to make GET requests to `https://sentry.io/api/0/...`
- `issue`: GET /api/0/projects/{org}/{project}/issues/{issue_id}/ -- output JSON to stdout
- `event`: GET /api/0/projects/{org}/{project}/issues/{issue_id}/events/{event_id}/ -- output JSON
- `events`: GET /api/0/projects/{org}/{project}/issues/{issue_id}/events/ -- output JSON
- Authorization header: `Bearer ${token}`
- Validate arguments, print usage to stderr on missing args
- Handle HTTP errors (non-2xx): print status and response body to stderr, exit 1
- Use async/await pattern with the https module (wrap in promise)
- CommonJS (require), no external dependencies

Create scripts/github-api.js -- GitHub CDN upload client (rewrite of upload.sh).

Interface:
  node scripts/github-api.js upload <file_path> [owner/repo]

Implementation:
- Shebang: #!/usr/bin/env node
- Get GitHub session cookie via: execSync(`node "${path.join(__dirname, 'keychain.js')}" get tb.github-session`, {encoding: 'utf8'}).trim()
- If retrieval fails, print "GitHub session not found. Run setup for pr-upload skill." to stderr, exit 1
- If owner/repo not provided, detect via: execSync('gh repo view --json nameWithOwner -q .nameWithOwner', {encoding: 'utf8'}).trim()
- Get repo ID via: execSync(`gh api /repos/${repo} --jq .id`, {encoding: 'utf8'}).trim()
- Replicate upload.sh flow in Node.js:
  1. POST to https://github.com/upload/policies/assets with form data (repository_id, name, size, content_type) and session cookie headers
  2. Parse policy response JSON for upload_url, form fields, asset_upload_url, asset_upload_authenticity_token, href
  3. POST file to upload_url with form fields from policy
  4. PUT to asset_upload_url to finalize asset
  5. Output href to stdout
- For HTTP requests with multipart form data: use child_process.execSync with curl commands (same approach as original upload.sh -- multipart form uploads with Node.js https are unnecessarily complex, curl handles it cleanly)
- Cookie header format: `user_session=${cookie}; __Host-user_session_same_site=${cookie}`
- Additional headers: Github-Verified-Fetch: true, X-Requested-With: XMLHttpRequest, Origin: https://github.com
- Verify file exists (fs.existsSync), detect content type via `file --mime-type -b`, get size via fs.statSync
- Validate arguments, print usage to stderr on missing args
- CommonJS (require), no external dependencies beyond Node.js built-ins
