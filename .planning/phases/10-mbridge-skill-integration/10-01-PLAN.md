Create `skills/mbridge/SKILL.md` (~500 lines) modeled on `skills/mobilecli/SKILL.md` structure but with fundamentally different content reflecting mbridge's self-contained command model.

**Frontmatter:**
```yaml
---
name: mbridge
description: Use when interacting with mobile apps on iOS simulators, Android emulators, or real devices. Use when tapping UI elements, navigating screens, testing mobile flows, verifying screen content, opening deeplinks, or automating any mobile device interaction.
allowed-tools: Bash(mbridge:*)
---
```

No `disable-model-invocation` (safe for auto-trigger -- read-only device interaction per context decision).

**Section order** (from 10-RESEARCH.md):
1. **Overview** -- Core principle: element targeting replaces dump+jq+tap. One mbridge command replaces the 3-step mobilecli pattern. No wrapper scripts, no bash helpers, no sourcing boilerplate.
2. **Quick Start** -- 4-5 command examples showing device list, tap by text, type into field, deeplink navigation, verify text. Each is a self-contained one-liner.
3. **Pre-flight Check** -- Poll `mbridge app foreground` until expected bundle ID appears. If app crashes, tell user to build/install it. No fixed sleep.
4. **Device Selection** -- Ask user when `mbridge device list` returns multiple. State tradeoffs (simulator vs real device). Same guidance as mobilecli.
5. **Command Reference** -- Full reference for all 5 groups. Document every flag from the source code:
   - `device`: list [--platform], boot, info
   - `app`: list, foreground, launch, open-url
   - `ui`: dump, find [--id, --text, --exact, --type, --xpath]
   - `action`: tap [--x, --y, --text, --id, --type, --exact, --unique], swipe DIRECTION [--distance, --text, --id, --type, --exact, --from], type TEXT [--text, --id, --type, --exact, --clear]
   - `verify`: text EXPECTED [--exact]
   - Global: --verbose / -v
   Include JSON output examples for key commands (device list, app foreground, ui find, action tap, verify text success/failure).
6. **Element Output Format** -- Document the normalized element schema: `{type, label, accessibility_id, bounds: {x,y,width,height}, center: {x,y}, enabled, visible, children}`
7. **Navigation Strategy** -- Priority order: (1) deeplinks via `mbridge app open-url`, (2) element targeting via `--text`/`--id`, (3) swipe + retry, (4) OCR verify as verification fallback. When to use deeplinks vs taps.
8. **Deeplink Pitfalls** -- Same-screen won't refresh (navigate away first). Cold start timing (poll foreground after launch). Keep it brief.
9. **Multi-step Automation Pattern** -- Batch 3-5 commands per Bash tool call with `&&`. Show example: `mbridge app open-url $DEV "myapp://signup" && mbridge action type $DEV "user@test.com" --text "Email" && mbridge action tap $DEV --text "Sign Up" && mbridge verify text $DEV "Welcome"`. Emphasize each command is self-contained, no sourcing, no env vars, no boilerplate.
10. **Subagent Pattern** -- For 5+ test flows, dispatch subagent. Single device = sequential only. Same concept as mobilecli but with mbridge commands directly.
11. **Cache Strategy (.mbridge/)** -- Permission logic (exists -> use silently; doesn't exist -> ask user once). File structure: `config.json` (device_id, bundle_id, deeplink_scheme) and `deeplinks.md`. Simpler than mobilecli -- no cache/*.json files because mbridge handles internal dumps. On first creation, add `.mbridge/` to `.gitignore` if not present. Include deeplink researcher subagent prompt template.
12. **Workflow Examples** -- 4-5 practical examples: navigate to screen, fill a form, scroll to find element, multi-step UAT flow. All using direct mbridge commands (no sourcing).
13. **Known Limitations** -- UIAutomator idle state issue on Android timer screens (same as mobilecli). Empty TextInputs may not appear in UI dump. OCR imperfect matching.
14. **Recommended Permissions** -- JSON snippet for Claude settings with `Bash(mbridge:*)`, `Bash(adb:*)`, `Bash(xcrun:*)`.
15. **Common Mistakes** (table format) -- 15-20 rows covering:
    - Writing bash wrapper functions (mbridge replaces test-helpers.sh)
    - Piping ui dump to file + jq (use `mbridge ui find` or `--text` flags directly)
    - Using coordinate-based taps when element targeting works
    - Forgetting --exact for ambiguous text
    - Using screenshots to check screen state (use ui find or verify text)
    - One operation per Bash tool call (batch with &&)
    - Fixed sleep after tap/navigate (poll foreground or verify text)
    - Guessing mbridge commands not listed here
    - Using BACK on Android at nav root (use deeplinks)
    - Re-opening same deeplink expecting refresh (navigate away first)
    - Sending commands before app ready (poll foreground after launch)
    - Running parallel subagents on same device (sequential only)
    - Skipping pre-flight check
    - Trying to build/install app yourself (ask user)
    - Using `xcrun simctl` or `adb` directly for things mbridge does
16. **Red Flags - STOP** (bullet list) -- 12-15 items mirroring Common Mistakes as "about to..." patterns.

**Platform-specific notes:** Only include behavioral differences per user decision:
- Android BACK exits app at navigation root
- UIAutomator idle state issue on timer/animation screens (Android)
- Empty TextInputs invisible in UI dump (React Native)

Do NOT include internal implementation details mbridge handles automatically (platform detection, coordinate conversion, dump caching).

**Part A: Create `scripts/checks/tool-mbridge.sh`**

Follow the established doctor check pattern from `scripts/checks/cred-sentry.sh`:
- Takes `$1` as PLUGIN_ROOT (defaults to ".")
- Checks three prerequisites:
  1. `mbridge --help` succeeds (CLI installed)
  2. `python3 --version` reports 3.12+ (parse version)
  3. `tesseract --version` succeeds (OCR dependency)
- Output format per check:
  - `PASS tool-mbridge mbridge CLI installed` or `FAIL tool-mbridge mbridge not installed. Run: node {PLUGIN_ROOT}/tools/mbridge/setup.js`
  - `PASS tool-mbridge-python Python 3.12+ available` or `FAIL tool-mbridge-python Python 3.12+ required`
  - `PASS tool-mbridge-ocr tesseract installed` or `FAIL tool-mbridge-ocr tesseract not installed. Run: brew install tesseract`
- Always `exit 0` (doctor checks never fail the process)
