**Frontmatter** (YAML between triple-dash delimiters at top of file):
- name: load-context
- description: Query and browse Forgetful memories for project context
- Do NOT set `disable-model-invocation` -- this skill should be model-invocable for workflow integration.

**Skill body structure (sections in this order):**

**Section 1 -- Resolve project scope:**
- Run `git remote get-url origin` to get repo identifier
- Call `execute_forgetful_tool("list_projects", {"repo_name": "<extracted-owner/repo>"})` to get project ID
- If no project found, warn user and continue without project scoping
- If git remote fails (not a git repo), warn user and query globally

**Section 2 -- Parse user query (per D-01):**
- `$ARGUMENTS` is the user's free-text query
- If `$ARGUMENTS` is empty, ask user what topic to search for
- Support optional flags: `--project <name>` (override auto-detected project), `--phase <number>` (add phase scoping to query), `--tags <comma-separated>` (filter by tags)
- Flags are parsed from `$ARGUMENTS` -- everything not a flag is the query text

**Section 3 -- Execute semantic query (per D-03):**
- Call `execute_forgetful_tool("query_memory", {...})` with:
  - `query`: the user's query text (if `--phase` provided, prepend "phase {N}" to query)
  - `k`: 15
  - `importance_threshold`: 7
  - `project_ids`: [resolved project ID] (omit if no project found)
  - `include_links`: true
  - `max_links_per_primary`: 2
- If Forgetful call fails, inform user that Forgetful is unreachable and suggest running `/tb:doctor` to diagnose. Stop.

**Section 4 -- Display filtered results (per D-02, D-03):**
- From returned results, filter to importance >= 7, cap at 8 results
- Display each memory as a titled block (per D-02, matching gsd-discuss-context.js output):

  ### 1. {title}
  **Importance:** {score} | **Tags:** {tags joined by comma}
  {content snippet, first 300 characters}...

- If zero results after filtering, report "No high-importance memories found for this query." and offer to try a different query.
- Show count: "Showing {N} of {total fetched} results (filtered to importance >= 7)"

**Section 5 -- Conversational refinement (per D-04):**
After displaying results, present three actions:

  **What would you like to do?**
  1. **Refine query** -- adjust search terms and re-run
  2. **Expand a memory** -- view full content, linked memories, and metadata (enter number)
  3. **Load into context** -- select memories to use in this conversation (e.g., "load 1,3,5")

**Refine:** Ask for new query, go back to Section 3 with new terms.

**Expand:** User gives a memory number. Call `execute_forgetful_tool("query_memory", ...)` with the memory's title as query, k=1 to get full content. Display:
- Full content (not truncated)
- Linked memories (from `include_links` response)
- Tags, keywords, creation date, last updated
- Then re-present the three action options.

**Load into context:** User specifies which memories by number (e.g., "1,3,5" or "all"). For each selected memory, output the full content in a structured block that persists in conversation:

  <loaded_memory source="forgetful" id="{memory_id}">
  **{title}** (importance: {score})
  {full content}
  </loaded_memory>

After loading, confirm: "Loaded {N} memories into context. These will be available for the rest of this conversation."

**Graceful degradation:** If any Forgetful MCP call fails at any point, report the error clearly and suggest `/tb:doctor`.

Create directory `skills/save-findings/` and write `SKILL.md` with the following exact structure:

**Frontmatter** (YAML between triple-dash delimiters at top of file):
- name: save-findings
- description: Extract and curate GSD phase artifacts into Forgetful memories
- Do NOT set `disable-model-invocation` -- this skill should be model-invocable.

**Skill body structure (sections in this order):**

**Section 1 -- Resolve project scope:**
Same pattern as load-context:
- Run `git remote get-url origin` to get repo identifier
- Call `execute_forgetful_tool("list_projects", {"repo_name": "<extracted-owner/repo>"})` to get project ID
- If no project found, ask user for project name and try again. If still no match, stop -- cannot save without project context.

**Section 2 -- Determine current phase scope (per D-05):**
- Read `.planning/STATE.md` to find current phase number and name from the "Current Position" section
- Read `.planning/ROADMAP.md` to find the phase's milestone version (e.g., "v1.1")
- If `.planning/` directory doesn't exist, inform user this skill requires a GSD project and stop.
- Report: "Scoping to Phase {N}: {name} (milestone {version})"

**Section 3 -- Read phase artifacts (per D-06):**
- Primary target: Read `.planning/phases/{phase-dir}/*-CONTEXT.md` -- this is the main extraction source
- Scan for additional artifacts in the phase directory:
  - `*-RESEARCH.md` (research findings)
  - `*-SUMMARY.md` files (plan execution summaries)
  - `*-PLAN.md` files (plan definitions -- low priority, mostly structural)
- Present list of found artifacts to user and ask which to include beyond the default CONTEXT.md:

  Found artifacts for Phase {N}:
  - [included] {phase}-CONTEXT.md (primary -- always included)
  - [ ] {phase}-RESEARCH.md
  - [ ] {phase}-01-SUMMARY.md
  - [ ] {phase}-02-SUMMARY.md
  Select additional artifacts to include (e.g., "1,2" or "all" or "none"):

**Section 4 -- Curation agent evaluation (per D-08, D-07 quality principles):**

Act as a curation agent. For each included artifact, read its content and evaluate sections for Forgetful-worthiness.

**Extraction categories (with importance ranges):**
- Architectural decisions with rationale: importance 8-9, tag `decision`
- Patterns established through iteration: importance 7-8, tag `pattern`
- Lessons learned from failures: importance 8, tag `lesson-learned`
- Technology choices with constraints: importance 7-8, tag `tech-choice`

**Quality gate -- evaluate each candidate on three axes:**
1. **Relevance longevity:** Will this still be useful in 3 months? If NO, skip.
2. **Atomic completeness:** Does the candidate stand alone without surrounding context? If NO, either enrich it or skip.
3. **Retrieval distinctiveness:** Will this create a unique semantic footprint vs existing memories? If NO, consider UPDATE instead of CREATE.

**Skip these categories (per D-07 research findings):**
- Current state/progress (stale within hours)
- Specific version numbers as facts (change silently)
- Specific file paths in implementation details (refactoring invalidates)
- Intermediate decisions later reversed

**Memory format for each candidate:**
- Title: `[Phase {N}] {concise descriptive title}` (max 200 chars)
- Content: Atomic, self-contained description with rationale (max 2000 chars). Must stand alone without needing to read the source artifact.
- Tags: auto-derived per D-10 -- artifact type tag (e.g., `decision`, `pattern`), phase tag (e.g., `phase-21`), milestone tag (e.g., `v1.1`)
- Keywords: 3-5 relevant terms for retrieval
- Importance: 7-9 based on category (see ranges above)

**Target: 3-7 candidates per phase.** If evaluating more than 7, tighten the quality gate. Better fewer high-quality memories than many mediocre ones.

**Section 5 -- Dedup check against existing memories (per D-11):**

For each candidate, query existing Forgetful memories:
- Call `execute_forgetful_tool("query_memory", {"query": candidate.title, "k": 5, "project_ids": [projectId]})`
- Compare returned memories against the candidate:
  - **Semantically identical content** -> action: SKIP (already saved)
  - **Similar but outdated existing memory** -> action: UPDATE existing memory ID with new content
  - **New information that supersedes old memory** -> action: CREATE new + OBSOLETE old memory ID
  - **Genuinely new, no overlap** -> action: CREATE

**Section 6 -- Opportunistic quality cleanup (per D-12):**

While scanning existing memories in Section 5, flag any that appear:
- Outdated (reference old decisions that were reversed in current phase artifacts)
- Contradicted by current artifacts
- Vague or not atomic (signs of poor curation from earlier saves)
Include these as additional OBSOLETE candidates in the batch with reasoning.

**Section 7 -- Present batch plan for review (per D-09):**

Display the complete curation plan as a table:

  ## Curation Plan ({N} actions)

  | # | Action | Title | Importance | Reasoning |
  |---|--------|-------|------------|-----------|
  | 1 | CREATE | [Phase {N}] {title} | 8 | {why this is worth saving} |
  | 2 | UPDATE #{id} | [Phase {N}] {title} | 7 | {what changed vs existing} |
  | 3 | OBSOLETE #{id} | {existing title} | - | {why outdated/superseded} |
  | 4 | SKIP | {candidate title} | - | {why not worth saving} |

  **Actions:** approve all, remove items by number (e.g., "remove 3,4"), or edit an item (e.g., "edit 2")

SKIP items are shown for transparency but not executed. User can:
- "approve" or "approve all" -- execute all non-SKIP items
- "remove 3,4" -- remove specific items from the batch
- "edit 2" -- modify title, content, importance, or tags of item 2
One review cycle only, not per-item.

**Section 8 -- Execute approved actions:**

For each approved action in order:
1. **CREATE:** Call `execute_forgetful_tool("create_memory", {title, content, context: "Phase {N} save-findings extraction", keywords, tags, importance, project_ids: [projectId]})`. Record the returned memory ID.
2. **UPDATE:** Call `execute_forgetful_tool("update_memory", {memory_id, title?, content?, importance?, tags?})` with the changed fields.
3. **OBSOLETE:** Call `execute_forgetful_tool("mark_memory_obsolete", {memory_id, reason, superseded_by})`. Use `superseded_by` if a CREATE in the same batch replaces this memory.

Report each action result:
  - CREATE #{new_id}: {title}
  - UPDATE #{id}: {title}
  - OBSOLETE #{id}: {title}

**Section 9 -- Summary:**

  ## Save Complete
  **Created:** {N} new memories
  **Updated:** {M} existing memories
  **Obsoleted:** {O} outdated memories
  **Skipped:** {S} candidates (not worth saving)
  Total Forgetful memories for this project: query with k=1 to estimate

**Graceful degradation:** If Forgetful is unreachable at any point, report the error clearly and suggest `/tb:doctor`. If `.planning/` directory is missing, report that this skill requires a GSD-managed project.
